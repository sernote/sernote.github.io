## Проблема

LLM cost часто сводят к `tokens * price`. Это пропускает cache hits, retries, fallbacks, failed tasks, latency impact и engineering cost.

## Симптомы

- Более дешёвая модель увеличивает retries.
- Более короткий prompt теряет prefix cache и становится дороже.
- Finance видит provider cost, но product не видит cost per scenario.

## Ментальная модель

AI Cost - это provider cost плюс GPU amortization, engineering cost, observability и evals, quality loss, latency impact, incident cost и opportunity cost.

## Архитектура

Cost attribution требует gateway metadata, provider pricing, cached token fields, scenario IDs, quality outcomes, retries, fallback events и business acceptance signals.

## Метрики

Самая сильная метрика - cost per accepted outcome: принятое CRM-письмо, корректная расшифровка, полезное summary, задача, прошедшая quality gate, или agent loop, который завершился в рамках budget.

## Компромиссы

Оптимизация cost per token может ударить по quality. Оптимизация под лучшую model может ударить по throughput. Оптимизация prompt length может ударить по cache. Зрелая экономика балансирует successful outcomes, latency и operating risk.

## Анти-паттерны

- Выбирать models только по price table.
- Игнорировать cached input token pricing.
- Считать retries невидимыми.
- Считать successful API calls вместо successful user tasks.

## Пример

Две модели могут иметь одинаковое raw количество input и output tokens. Если одна сохраняет cached prefixes между agent turns, а другая теряет cache из-за tool drift, их effective cost может резко разойтись.

## Шаблон решения

Пиши cost decisions так: scenario, model/provider options, raw token cost, cache-adjusted cost, retry rate, quality pass rate, latency, accepted outcome rate и owner.
