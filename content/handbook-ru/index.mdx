## Проблема

Большинство AI-инициатив начинается с работающего demo, а затем обнаруживает настоящую систему: gateway, routing, inference, cache, evals, observability, cost, guardrails, incidents и ownership.

## Симптомы

- Продуктовые команды напрямую вызывают разных providers.
- Смена модели выкатывается как правка config, а не как release.
- Cost считается по provider invoice, а не по accepted outcome.
- Cache включён, но никто не может объяснить hit rate.
- Качество оценивается по ощущениям, пока regression не доходит до пользователей.

## Ментальная модель

Production AI - это не модель. Это платформа.

Модель заменяема. Платформа накапливает эффект.

## Метрики

Отслеживай request volume, scenario success, accepted outcomes, input tokens, output tokens, cached tokens, TTFT, TPOT, total latency, fallback rate, quality gate pass rate и cost per accepted outcome.

## Компромиссы

Managed APIs снижают операционную нагрузку, но могут скрывать cost и routing mechanics. Self-hosted inference даёт контроль, но переносит capacity, reliability и model lifecycle на platform team.

## Анти-паттерны

- Считать один provider SDK архитектурой.
- Оптимизировать raw token count и ломать prefix cache.
- Выкатывать новые model names без evals, canary или rollback.
- Строить product-specific AI stacks, которые не могут делить telemetry или policy.

## Пример

Production-like CRM assistant может начаться как один prompt и одна model. Platform version добавляет gateway, стабильные tool definitions, prefix-aware routing, scenario evals, trace-level cost и owner для fallback behavior.

## Шаблон решения

Оформи решение так: scenario, user value, risk level, provider strategy, quality gate, observability fields, cost guardrail, fallback path и owner.
