## Проблема

"Модель вроде отвечает хорошо" - это не quality process.

## Симптомы

- Model changes выкатываются без scenario datasets.
- Prompt edits не проходят regression tests.
- LLM-as-a-judge scores есть, но failures никто не доверяет.
- Production feedback не обновляет dataset.

## Ментальная модель

Quality Gate - это не один score. Это loop, который не даёт платформе деградировать незаметно.

## Архитектура

Dataset -> eval suite -> error taxonomy -> prompt/model change -> regression -> canary -> production feedback -> dataset update.

## Метрики

Измеряй scenario pass rate, critical error rate, regression delta, judge agreement, manual review load, canary stop events, feedback acceptance и cost per passed task.

## Компромиссы

Строгие gates замедляют releases, но предотвращают invisible degradation. Слабые gates сохраняют скорость, но переносят quality risk на users. Правильный gate зависит от scenario risk.

## Анти-паттерны

- Golden datasets, которые никогда не получают production failures.
- Один aggregate score, скрывающий critical categories.
- Judge prompts без versioning.
- Canary rollout без stop criteria.

## Пример

Новая summarization model может пройти generic benchmarks и всё равно провалить product needs, если пропускает CRM-specific action items. Gate должен включать scenario examples и task-level acceptance metric.

## Шаблон решения

Каждый rollout должен включать dataset, metrics, threshold, regression delta, canary plan, fallback, owner и release note.
