## Problem

Guardrails are often added after an incident. Then they become scattered filters, not part of the platform contract.

## Symptoms

- Each product team decides what to log and redact.
- PII handling differs by scenario.
- Tool execution risk is discussed only after something breaks.
- Safety events do not enter traces or cost review.

## Mental model

Guardrails are policies, telemetry, fallback and ownership. A library can help, but it does not replace the operating process.

## Architecture

A minimum layer includes input policy, output policy, PII handling, prompt injection checks, tool execution boundaries, audit trail, fallback behavior and human review for high-risk scenarios.

Semantic Router can be the first safety gate: before starting an agent, tool use or external action, it chooses a safe lane, human review or policy denial.

Policy fields: `policy_route`, `allowed_tools`, `blocked_tools`, `requires_human_confirmation`, `tool_budget` and `action_scope`.

## Metrics

Track safety event rate, blocked requests, false positive rate, fallback rate, manual review load, policy version, audit completeness and incident count.

## Trade-offs

Strict policies reduce risk, but can break useful workflows. Weak policies preserve UX, but move risk into production. Use scenario-level risk, not one global filter.

## Anti-patterns

- Treating guardrails as one library.
- Treating open weights as automatically valid for commercial production.
- Not versioning policy.
- Not logging safety events.
- Giving agents tools without budget, scope or audit.

## Checklist

<Checklist
  items={[
    "The scenario has an explicit risk level.",
    "Input and output policies are versioned.",
    "PII handling is defined before rollout.",
    "Model license is checked before production release: commercial use, limits, fine-tuning, distillation and distribution.",
    "Tool execution has scope, budget and audit trail.",
    "Fallback and human review path are known before an incident."
  ]}
/>

## Example

If an assistant can trigger an external action, the guardrail must inspect more than response text. It needs tool-call scope, audit event, fallback to manual approval and a trace field for the policy decision.

## Decision template

For each scenario, document: risk level, policy version, blocked classes, allowed tools, fallback, human review owner, audit fields and incident escalation.
